⚡ ContinualEdge 系统设计：端侧 LLM 持续自适应运行时

2026-05-20 · System Design · Jiaxin Luo

1. 问题定义

当前工业现场 Agent 存在三重依赖困境：

  • 网络依赖：云端 LLM 方案在电梯井道、地下机房等场景失效；
  • 数据依赖：垂直 Agent 需要企业私域数据训练，但维保行业数据极度碎片化；
  • 算力依赖：工业级边缘设备（如执法仪）仅配备低功耗 ARM 芯片与 3GB 级内存，无法承载标准 LLM 推理。

本方案构建零私域数据、端侧闭环、法规驱动的边缘 Agent 系统，解决特种设备维保场景的"最后一公里"智能交互问题。

2. 核心抽象：Domain Adapter Card

每个维保任务域被抽象为一张 Adapter Card，包含以下字段：

3. 系统总体架构（四层）

Layer 4: User Space — Agent Applications

  • 维保对话 App（语音交互前端）
  • 视觉质检 App（拍照+缺陷定位）
  • 工单生成 App（结构化输出）
  • 每个 App = 一个 Domain Adapter + 一套 Tool Registry

Layer 3: Kernel Space — ContinualEdge Runtime

  • Domain Scheduler：基于 Fingerprint 的 Top-K Adapter 检索与加载
  • Model Lifecycle Manager：Base Model 常驻区 + Adapter 缓存池（LRU）+ Merge Compactor
  • Continual Learning Engine：梯度累积、Few-shot Buffer、灾难性遗忘监控
  • Fingerprint Compute Engine：ARM NEON 优化的层-wise 均值/协方差计算
  • Resource Governor：温度节流、电量感知调度、内存压力处理

Layer 2: Edge-Cloud Sync

  • 差分同步协议（法规库更新、模型热补丁）
  • 离线优先队列（工单 > 日志 > 诊断音频）
  • 网络感知调度器

Layer 1: Cloud Backend

  • Go-Fiber API 网关
  • 法规知识库管理（PostgreSQL + pgvector）
  • 模型分发服务（OTA 量化模型推送 + A/B 版本管理）
  • 交互审计日志（Event Sourcing）

4. Domain Scheduler：基于指纹的 Adapter 调度

不是用关键词匹配，而是用表示空间几何距离（ICLR 核心思想）。

  1. 输入编码：技师语音转文本后，过 Base Model 前 8 层，提取隐藏层状态 H ∈ R^(seq_len × hidden_dim)。
  2. 在线指纹计算：在 ARM NEON 上并行计算 H 的层-wise 均值 μ 和协方差 Σ（优化后延迟 << 50ms）。
  3. 相似度检索：与本地 Adapter Card 库中的指纹做 CKA + Wasserstein-2 混合度量。
  4. Top-K 加载：取 Top-2 相似 Adapter，如果相似度 > 0.85 且差距 > 0.1，直接加载 Top-1；如果接近，触发分层加权合并。

5. Model Lifecycle Manager：Adapter 的换入换出

N1 只有 3GB 内存，Base Model 占 2.1GB，留给 Adapter 的不到 900MB。

  • 常驻集（Resident Set）：最近 5 个任务的 Adapter，常驻内存，LRU 淘汰。
  • 交换区（Swap Area）：冷 Adapter 序列化为 GGUF，Zstd 压缩后存本地文件系统（64MB → 20MB）。
  • 挂载机制：运行时动态替换 LoRA 权重，要求 llama.cpp 支持上下文保持下的 Adapter 热切换。

6. Continual Learning Engine：端侧增量学习

学习模式触发条件：

  • 技师连续 3 次纠正 Agent 的回答
  • 检测到新设备型号（二维码解析出未在知识库的型号）
  • 人工触发"学习模式"（长按执法仪某键）

端侧训练流程：

  1. 样本采集：收集技师纠正的（问题，正确回答）对，最多 10 条。
  2. 冻结 Base Model，初始化新 LoRA（r=8，参数量约 5MB）。
  3. 本地微调：3-5 个 epoch，梯度累积，学习率 1e-4。
  4. 指纹提取：微调完成后，用新样本跑前向，计算新 Adapter 的 Domain Fingerprint。
  5. 相似度检查：与现有 Adapter 库比对。若与某现有 Adapter 相似度 > 0.9，合并；若 < 0.6，注册为新 Domain。
  6. 遗忘监控：合并后，在本地保留的验证集上测试，若某旧 Domain 准确率下降 > 5%，拒绝合并。

7. 学术价值与投稿规划

核心学术问题：如何在内存 << 3GB、无 GPU、网络不稳定、多任务持续到来的边缘设备上，实现大语言模型的持续自适应与生命周期管理？

目标会议：

  • 首选 UbiComp/ISWC 2026（CCF-A，边缘智能 + 普适计算）
  • 次选 ASPLOS 2027（CCF-A，系统实现深度）
