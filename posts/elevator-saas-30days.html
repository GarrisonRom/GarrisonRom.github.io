电梯 SaaS 创业 30 天：从 0 到 Demo 的技术决策复盘

2026-04-20 · Engineering · Jiaxin Luo

背景

这是一个个人商业项目（非实验室课题），目标是为物业和维保公司提供法律风控级电梯维保 SaaS。技术栈：Kotlin Multiplatform（Android）+ Go 1.22（Fiber）+ PostgreSQL 16 + Redis + RabbitMQ + MinIO。

第一周：Clean Architecture + DDD

一开始决定用 Clean Architecture + DDD，现在回头看，对于一个人开发的 MVP 来说有些过度设计。但好处是：当我需要把离线队列模块拆成独立服务时，边界非常清晰。

关键妥协：

  • Go-Fiber 缺少成熟 ORM，暂定使用 sqlx + scany 手写 SQL；
  • Event Sourcing 性能：PG 单表 events 预计月增 100 万行，需提前设计分区（按月份）；
  • 执法仪 Camera2 API 与 Compose 预览 Surface 兼容性问题，备选 TextureView。

第二周：Kotlin Compose + 执法仪集成

海康 DSJ-HIKN1A1 执法仪（Android 9.0，2.4 寸屏，3300mAh）。核心难点：

  • 屏幕适配 240×320 分辨率，按钮最小 44px；
  • 离线照片存储策略：SQLite 存元数据，本地文件系统存图片；
  • 海康 N1 拍照延迟约 300ms，需防抖处理；
  • 4G 流量敏感，照片压缩至 800KB 以下再上传。

第三周：VRPTW + Event Sourcing

VRPTW（带时间窗的车辆路径规划）算法 Go 库生态薄弱，最终妥协：用 Python 微服务（ortools）通过 gRPC 调用，Go 端只负责调度。

Event Sourcing 一度让我陷入"为了审计而审计"的陷阱，后来简化为只记录关键业务事件：TaskCreated、PhotoUploaded、PropertyConfirmed。

第四周：联调与反作弊

反作弊机制：

  • GPS 校验：维保地点与电梯注册坐标偏差 > 100 米触发预警；
  • 照片水印：设备 ID + 时间戳 + GPS 坐标合成不可见水印；
  • 时间校验：维保时长低于标准工时 50% 标记异常。

教训总结

  1. AI 生成 80% 样板代码，人工聚焦 20% 业务逻辑：水印合成、离线队列、执法仪通信协议；
  2. 范围严格锁定：不要碰预测性维护、不要碰 AI 诊断，只做流程数字化；
  3. 保密第一：代码仓库私有（Gitee），个人设备开发，个人域名演示，非学校 IP。
